public List<Flight> getAllFlightsFromCityToCity(String departure_city, String arrival_city) {
    String sql = "SELECT * FROM flight WHERE departure_city = ? AND arrival_city = ?";
    List<Flight> flights = new ArrayList<>();

    try {
        PreparedStatement ps = connection.prepareStatement(sql);
        ps.setString(1, departure_city);
        ps.setString(2, arrival_city);

        ResultSet rs = ps.executeQuery();
        while(rs.next()) {
            Flight flight = new Flight(
                rs.getInt("flight_id"),
                rs.getString("departure_city"),
                rs.getString("arrival_city")
            );
            flights.add(flight);
        }
    } catch(SQLException e) {
        System.out.println(e.getMessage());
    }
    return flights;
}

public int count(String in) {
    if (in == null || in.length() == 0) {
        return 0;
    }

    int count = 1;
    for (int i = 0; i < in.length(); i++) {
        if (in.charAt(i) == ' ') {
            count++;
        }
    }
    return count;
}
public boolean check(int[] arr, int target) {
    for (int i = 0; i < arr.length; i++) {
        for (int j = i + 1; j < arr.length; j++) {
            if (arr[i] + arr[j] == target) {
                return true;
            }
        }
    }
    return false;
}
public String removeAll(String str, String ch) {
    StringBuilder result = new StringBuilder();
    for (int i = 0; i < str.length(); i++) {
        if (str.charAt(i) != ch.charAt(0)) {
            result.append(str.charAt(i));
        }
    }
    return result.toString();
}

Key Concepts

Core ideas I apply in every project.

Layered Architecture Pattern

HTTP Request → Controller → Service → DAO → Database

Each layer has one responsibility. Changes to the database do not directly affect the controller.

Database Design

  • Primary Key: Unique identifier for each row
  • Foreign Key: Links to another table
  • PreparedStatement: Prevents SQL injection attacks
  • ResultSet: Container of rows returned from a query

REST API Design

  • GET = Read/retrieve data
  • POST = Create new resource
  • PUT = Update entire resource
  • DELETE = Remove resource
  • Status Codes: 200, 400, 500

Testing Strategy

  • Write tests FIRST (TDD)
  • Use assertions to verify behavior
  • Mock dependencies for isolated testing
  • Test business logic, not just happy paths

SOLID Principles

  • Single Responsibility
  • Open/Closed
  • Liskov Substitution
  • Interface Segregation
  • Dependency Inversion
